## Дерево маршрутів

```
/                         → redirect { name: 'products' }
/products                 ProductsLayout            meta.breadcrumb: Каталог
├── ''                    ProductCatalogView        name: products
└── :id                   ProductLayout             meta.breadcrumb: dynamic product
    ├── ''                ProductOverviewView       name: product-overview
    └── reviews           ProductReviewsView        name: product-reviews, meta.breadcrumb: Відгуки
/about                    AboutView                 name: about, meta.breadcrumb: Про застосунок
/:pathMatch(.*)*          NotFoundView              name: not-found, meta.breadcrumb: Сторінку не знайдено
```

Дочірні шляхи `:id` і `reviews` не починаються з косої риски й доповнюють шлях предка.
Порожні дочірні шляхи визначають вміст за адресою самого батьківського рівня; імена мають
кінцеві представлення, а не оболонки.

| `ProductLayout.vue` | Власник даних товару: URL за `params.id`, `useFetch`, стани завантаження/помилки/відсутності, спільна оболонка, передавання `product` через слот `RouterView` | Не виконує запиту під час перемикання розділів |
| `ProductOverviewView.vue`, `ProductReviewsView.vue` | Представлення одного розділу товару за пропсом `product` | Не виконують HTTP-запитів |

| `useFetch.js` | Запит, `AbortController`, очищення старих даних, перевірка `response.ok`, статус помилки, `null` як відсутній URL | Не знає, який компонент показує дані |
| `useDebouncedValue.js` | Відкладене значення з очищенням таймера | — |
| `useIntersectionObserver.js` | Підписка на перетин маркера та `disconnect()` | — |
| `ProductSearchForm`, `ProductCatalog`, `ProductCard`, `CatalogLoadMore` | Компоненти представлення з роботи 5; назва картки є `RouterLink` на огляд товару зі збереженим `q` | Не виконують запитів і не змінюють маршрут самостійно |

## Метадані хлібних крихт

| Запис маршруту | `meta.breadcrumb` | Підпис у крихтах |
| --- | --- | --- |
| `/products` (ProductsLayout) | `{ label: 'Каталог', name: 'products' }` | Каталог |
| `:id` (ProductLayout) | `{ dynamic: 'product', name: 'product-overview' }` | «Товар №id» до відповіді, назва товару після неї, «Товар не знайдено» для відсутнього |
| `reviews` | `{ label: 'Відгуки', name: 'product-reviews' }` | Відгуки |
| `/about` | `{ label: 'Про застосунок', name: 'about' }` | Про застосунок |
| `/:pathMatch(.*)*` | `{ label: 'Сторінку не знайдено', name: 'not-found' }` | Сторінку не знайдено |

Порожні дочірні маршрути каталогу й огляду поля `breadcrumb` не мають, тому рівень не
дублюється. `useBreadcrumbs` перебирає `route.matched` від предка до нащадка, бо об’єднане
`route.meta` перекриває однакові ключі й не зберігає опис кожного рівня. Для рівнів товару в
`to` додається `params.id`, а рядковий `q` зберігається в `query`.

## Розподіл стану між query, params і завантаженим товаром

- **`params.id`** визначає ресурс: `ProductLayout` обчислює за ним URL API. Перехід між
  оглядом і відгуками не змінює `id`, тому новий запит не виконується; зміна `id` перезапускає
  `useFetch` у тому самому екземплярі оболонки, а старий запит скасовується.
- **`query.q`** — підтверджена умова пошуку. Каталог формує за нею запит, а посилання карток,
  розділів і крихт передають `q` далі, тож повернення до каталогу відновлює пошук. Текст у полі —
  локальна чернетка: після паузи 400 мс вона записується в `q` через `router.replace()`.
- **Завантажений товар** належить `ProductLayout` і передається дочірнім представленням пропсом
  через слот `RouterView`; назва товару потрапляє в крихти без окремого запиту.

## Виробнича збірка й preview

```bash
npm run build
npm exec vite preview -- --port 5176 --strictPort   # у PowerShell: '--'
```

Через `vite preview` перевірено пряме відкриття та reload `/products/12`, `/products/12/reviews` і
`/products/12/reviews?q=phone`: документ повертається зі статусом 200, підключається зібраний
`/assets/index-*.js`, товар завантажується одним запитом. Готове посилання `/products?q=phone`
відновлює пошук, `/` перенаправляє на каталог, невідома адреса показує сторінку 404.

### Вимоги до виробничого сервера

`createWebHistory()` записує шлях маршруту звичайною частиною URL. Після оновлення сторінки
або прямого відкриття `/products/12/reviews` браузер запитує цей шлях у сервера, тому сервер має
повертати `index.html` для всіх адрес застосунку, зберігаючи окрему обробку статичних файлів і API.
`vite preview` робить це автоматично; для nginx правило має такий вигляд:

```nginx
location /assets/ {
  try_files $uri =404;
}

location / {
  try_files $uri $uri/ /index.html;
}
```

Сторінка «Сторінку не знайдено» формується на клієнті, тому сам документ повертається зі
статусом 200. Якщо застосунок розміщено не в корені домену, шлях задається через `base` у
конфігурації Vite, а маршрутизатор отримує його через `import.meta.env.BASE_URL`.
`node_modules` і `dist` виключено з Git через `lab6/.gitignore`.
